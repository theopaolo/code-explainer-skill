# The interactive site (Artifact)

Start from `assets/site-template.html`. Full worked example: `references/example/paletcam_site.src.html`
(9 chapters, canvases driven by the real extraction code).

## Structure

- Hash-routed single page: each `<section class="page" data-page="id" data-title="…" [data-step="n"]>`
  is a chapter; the TOC, mobile select, prev/next pager and ←/→ keys are generated by the template JS.
- Chapter order: Home (thesis + video + chapter buttons + step cards) → theory chapters (the
  problems that motivate the design) → one chapter per pipeline step (numbered, they are a real
  sequence) → special modes → glossary (terms, writing method, source files table).
- Chapter body pattern: eyebrow → h1 → prose (what) → formula → interactive figure → `.why` blocks →
  "Termes techniques" table → Note/Attention callouts.

## Pipeline overview diagram (home page)

The user asked for "a global explorable overview of what the video says". Use
`assets/pipeline-diagram.html` (CSS + markup + JS, instructions in its header comment):

- A CSS-grid flow of clickable nodes: theory concepts (dashed) at the top, input, then each step
  in order, grouped in dashed **lanes** (threads, stages, alternative modes), feedback loops as
  dashed accent edges. Step keys (1, 2a, 3c, P1…) match the chapters.
- Clicking a node fills a sticky side panel: what / why / technical terms / key values /
  "▶ Vidéo m:ss" (seeks + plays the video) / "Ouvrir le chapitre".
- While the video plays, the narrated node is ringed and the panel follows (unless the user
  clicked within 6 s). Prev/next buttons walk the reading order.
- Node timestamps: `scripts/node_times.py` with a `{node: [scene_key, sentence fragment]}` map.
- Edges are SVG paths recomputed from node positions; route a side branch out of the node's
  right side, feedback loops via side curves, and hide long cross-diagram links on phones.
- Prefer this over Mermaid inside an Artifact: Mermaid's layout can't use the page tokens,
  handle clicks, or sync to the video reliably.

## Interactive figures

- Each chapter gets one figure that lets the reader *poke the mechanism*: a slider that changes
  a real parameter and redraws, a click that moves a probe, an "animate" button, an upload.
- Drive them with the **real project code**: bundle the modules with `scripts/bundle_lab.sh` into
  `lab.js` (IIFE setting `globalThis.Lab`). Export intermediate stages too (the shipped API often
  returns only the final result — write a small entry that re-runs the same steps and keeps every
  stage for display). Note any part re-implemented for illustration (e.g. a 2D projection of a 3D
  algorithm) in the caption.
- Open every demo in a working state (sample image loaded, defaults = the product's defaults).
- Canvas colors come from CSS tokens at draw time (`css("--accent")`), and every demo registers a
  `redraws[id]` so it repaints on theme change.
- Real-time simulations: pause when the chapter is hidden; start paused under
  `prefers-reduced-motion`.
- Use the product's real constants in simulations (a smoothing factor of 0.18 vs the real 0.16 is
  a bug the user will catch).

## Artifact constraints (from the Artifact tool contract)

- Load the `artifact-design` guidance (or run Artifact `quickstart`) before the first publish.
- Only Google Fonts load externally → inline the project font as data URIs (`build_site.py --font`).
- Extra files (lab.js, images, mp4, poster) go in `files` on publish; images ≤ ~60 KB each
  (resize to 720 px, JPEG q5). Binary files ≤ 15 MB each.
- No downloads, no print, no `alert`; hash deep-links only as bare tokens (`#choisir`).
- Theme-aware: tokens on `:root`, dark redefinitions under the media query guard and
  `[data-theme]`; explicit `body` background.
- Republish with the same file path to keep the URL. Mention the link is private until shared.

## Verification

- `build_site.py` syntax-checks the page script.
- `scripts/screenshot.mjs` (playwright-core + any installed Chromium: Helium, Chrome, or the
  ms-playwright cache) screenshots each chapter at desktop-dark and phone-light, and reports page
  errors and horizontal overflow. The chrome-devtools MCP may fail to find Chrome while this works.
  It caught a real bug in the reference build: a demo drew before its image had loaded.
- Look at the screenshots (Read tool) once, fix, re-check once. Guard every demo's draw() against
  "data not loaded yet", because the router calls redraw on first visit.
